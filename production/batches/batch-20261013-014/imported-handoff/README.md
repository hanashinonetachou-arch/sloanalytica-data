## 内容
- `candidates.json`: 出典付き候補、設定別数値（分母を逆数表記の値として保持）、入力とdependencyの設計上の暫定区分。
- `candidate_index.csv`: 候補一覧（Excel等で可読）。
- `coverage.csv`: 6領域×10機種の監査表。部分確認と未確認を厳格に区別。
- `work_handoff.md`: Workでの不足補完と量産工程向け指示。

## 設計に関する注意
- `settings` が per_game の候補は、設定別「1/x」の x を格納する。条件付き抽選や一部カテゴリ値は別形式。`null` は欠測であってゼロではない。
- `statistics_candidate` は採用確定を意味しない。正式な選択スコアやEligibilityは未計算。
- 複数の初当り/CZ/ATは関連する。掛け合わせず、代表値1つまたは条件付き分解モデルを選ぶ。
- `exact_and_unknown` は定性的示唆と確定制約を混在させた調査候補。Workでイベント別に分割し、制約だけを推測制約として実装する。
- 状態が見えない移行・チェリー契機の結果・AT中確率は観測可能性と母数に注意。
- 個別サイトの「濃厚」「確定」表現、数値の信頼度、設定非搭載区分を再検証する。
- リセット、CZ内部状態、分母に関する抜けが残るため、全体の調査完了とはしない。

## UIの基礎
- ゲーム数母数には総G/通常G/ボーナス中Gを区別。AT・CZ等の数値は1/x、結果分布は%を使用。
- 条件付きイベントには『対象時のみ+1』、推測に使えない場合は理由を平易に示す。
- 数値不明の示唆は記録のみ、確定・否定は正確な条件が確認できた場合のみ制約として使う。
