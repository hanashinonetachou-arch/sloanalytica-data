添付ZIPの `HANDOFF_MANIFEST.json` と `HANDOFF_GAP_MATRIX.md` をまず読み、01〜10の機種順を固定して作業を開始してください。確認報告のみで止まらず、自律的に実行します。既存ファイル10機種分のResearchモデルと個別終了記録は再利用してください。**未完了を完了済みに書き換えてはなりません。**

## 正本・工程の境界
- Data: `hanashinonetachou-arch/sloanalytica-data`; App: `hanashinonetachou-arch/sloanalytica-app`。
- `main` だけを最新量産状態と決めつけず、既存のProduction Batchブランチ・最新Production State・既存機種ID・候補・Manifest v8.5・Research終了契約・validator・機種同定の正本を確認してください。過去に確認できた `production/v85-batch-024-contract-20261020` は参照点にすぎず、最新と決めつけません。
- 既存Batch、機種ID、Work IDの推測生成や二重初期化は禁止。発見済み既存候補・保存履歴・設定推測モデル・QA状態を保持し、削除しません。
- Chat側Research終了記録（10/10）は**公開情報の有界調査に関する記録**です。Repository上の正式 `RESEARCH COMPLETE`（未確認）と同一視しません。

## 実行ループ（必ず1機種ずつ）
1. `HANDOFF_MANIFEST.json` に記載された順で1機種を選ぶ。10機種全体の先行総点検は禁止。
2. 対応する `xx_*.md`、`xx_*CLOSED.md`、`xx_status.json` を読み、既存Repository候補・所属Batch・Machine IDを照合して既存成果物を再利用する。
3. 欠落・矛盾・未照合箇所だけ標準調査範囲（なな徹／DMMぱちタウン／ちょんぼりすた／一撃／パチ7／該当メーカー3サイト）で調査・6領域の自己監査。特に機種04〜10の5サイト照合証跡は未完了と明示されている。確認できない場合は調査済み・未公表として理由を残して閉じる。無期限の再検索や独自候補数ノルマは禁止。
4. 観測条件・母数・数値・出典・包含・条件付き・排他・重複の関係とUI案を確定。記録のみ、Exact Constraint、数値モデルを区別。資料間の未解決差異は勝手に補完しない。
5. その機種のResearch終了契約に基づいて成果物と監査・停止根拠・再開条件を保存。Repositoryの正式Research承認／バリデータに必要なデータを満たす場合のみステージ遷移を行い、記録を残す。未完了・外部制限は正確に明示する。
6. **保存が完了してから**次機種へ。各機種でユーザーの承認待ち停止は禁止。例外が人の判断を本当に必要とする場合は `HUMAN_REQUIRED` とし、作業可能な他機種を進める。

## 10機種のResearch正式受理後
- 正本と既存Contractに従い `Evaluation → Eligibility → Candidate Contract` を連続実行し、二重計測を防ぐ条件付きモデル・数値未公表候補・出典・不採用理由の追跡性を維持する。
- EIG7000×200（CORE≥20 / SUPPORT10–<20 / JOINT_ELIGIBLE5–<10 / EXCLUDE<5）は**正式Evaluationでのみ**判定する。Chat資料の「候補」を採用確定に読み替えない。
- 所定のWork用成果物と差分・残るHUMAN_REQUIREDをまとめる。実装・配信・APK・実機QAは今回の対象外で、既存QAの完了状態は変更しない。
- GitHub ActionsはIntegration Boundary中心に節約し、Work停止・再開は保存済み正本から行う。Researchの調査履歴を無意味に作り直さない。

## 固有注意
- バキ：強喰設定5の数値衝突と確定強喰の観測条件を勝手に埋めない。
- リノヘブン：32G連チャンと初当り・通常時3枚ベル分母を区別。
- ハナビ：旧新ハナビと混同せず、ピース花火はRB中1枚役条件付き。
- アレックス：REG壁画調は確定演出ではなく確率差、BIG契機別合算は二重掛算しない。
- クレアBT：BTハズレの未公表設定確率を補間しない。
- マジハロBT：虹アリストロフィーは旧機種類推につき本機設定6確定にしない。
- SHAKE BT：JAC3分類を排他カテゴリ化し、継続率を別掛算しない。
- ニューキングハナハナV：設定Vは固有で5/6に置換禁止。スマート機と30Φ版を分離。
- サンダーV：1G連専用の画面条件と通常BIG終了画面を分離。
- ケロット5BT：金帯②は絵柄が鍵。旧作由来のトロフィー示唆を確定させない。

## ユーザー向け共通UI
- 数値未公表でセクションの全項目が参考記録の場合：「このセクションの全項目は設定別出現率が公表・確認されていないため、記録のみです。設定推測の計算には使用しません。」と明示。
- ゲーム数の総G・通常G、観測回数の母数を区別し、共通入力を再利用。内訳から自動算出できる「その他」は重複入力しない。
- 同じ観測機会は可能な範囲でタブ統合。説明が同じ不採用要素は枠を共通化し、対象名は1件ずつ箇条書きにする。出典サイト名はユーザー向け説明へ出さない。
